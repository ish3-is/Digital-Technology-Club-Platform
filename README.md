# المقر الرقمي — نادي التقنية الرقمية

تطبيق عربي RTL لنادي التقنية الرقمية بجامعة الملك خالد. النسخة الحالية تنفذ **المرحلة الثالثة فوق المراحل السابقة**: مهام واعتماديات وطلبات بين اللجان واجتماعات وقرارات ومراجعات ووارد موحد ومرفقات خاصة وبحث مقيد بالصلاحيات. الفعاليات أصبحت غرف عمليات بمتطلبات جاهزية وفريق وحضور ومخاطر واعتماد وتقرير نهائي. الإنجازات والمعرفة تبقيان للمراحل التالية.

## التشغيل المحلي

المتطلبات: Node.js 24 وnpm. لا تحتاج Docker للتطوير؛ PGlite يشغل PostgreSQL محليًا. لا تستخدم أكثر من عملية على نفس مجلد البيانات.

```powershell
npm ci
Copy-Item .env.example .env
# ضع سرًا عشوائيًا طويلًا في BETTER_AUTH_SECRET داخل .env
npm run db:migrate
npm run dev
```

افتح http://localhost:3000 . لا يوجد حساب افتراضي أو كلمة مرور ثابتة. ملف .env المحلي المجهز في هذه الجلسة يحوي سرًا عشوائيًا ولا يدخل Git.

## إنشاء أول مدير

أوقف خادم التطوير قبل استخدام أدوات CLI مع PGlite. اختر بريدك واسمك الفعليين بدل القيم التالية. كلمة المرور ١٢ حرفًا على الأقل ولا تمررها كوسيط أمر.

```powershell
$env:CLUB_INITIAL_PASSWORD = Read-Host 'كلمة المرور الأولية' -MaskInput
npm run provision -- 'your-email@example.com' 'اسم المسؤول' system_admin
Remove-Item Env:CLUB_INITIAL_PASSWORD
npm run dev
```

تُنشأ الهوية في قاعدة البيانات وكلمة المرور مجزأة عبر Better Auth، ثم تكتمل التهيئة عند أول دخول. إدارة الحسابات مغلقة على الأدوات المحلية الموثوقة في هذه المرحلة.

## التنظيم

```powershell
npm run org -- committee media 'اللجنة الإعلامية'
npm run org -- term term-1 'الفصل الأول' 'العام الأكاديمي المعتمد' 2026-09-01 2027-01-31
npm run org -- assign 'member@example.com' committee_head media term-1
npm run org -- disable 'member@example.com'
npm run org -- enable 'member@example.com'
npm run org -- close-term term-1
```

تواريخ المثال ليست فصلًا جامعيًا معتمدًا؛ استبدلها بالتواريخ الرسمية. إغلاق الفصل ينهي تعييناته ويحفظ التاريخ. أسماء الأدوار الداخلية في src/db/catalog.ts. أدوات التنظيم موثوقة وتعادل صلاحية تشغيل الخادم، فلا تمنحها للمستخدمين العاديين.

## الفحوص

```powershell
npm run typecheck
npm test
npm run build
```

اختبارات التكامل تستخدم PostgreSQL في الذاكرة دون المساس ببيانات التشغيل. تشمل: المصادقة، التهيئة، IDOR، تعطيل الحساب، انتهاء النطاق، أصل الطلب، تراجع المعاملة، التدقيق، واستعادة كلمة المرور أحادية الاستخدام عبر ناقل بريد اختباري.

اختبار Edge يتطلب قاعدة منفصلة؛ في نافذة PowerShell أولى:

```powershell
$env:PGLITE_DIR = '.data/e2e-' + [guid]::NewGuid().ToString('N')
$env:BETTER_AUTH_URL = 'http://localhost:3001'
npm run db:migrate
node --env-file=.env --import tsx scripts/seed-work-e2e.ts
npm run dev -- --port 3001
```

وفي نافذة ثانية: `npm run test:e2e`. الحسابات التجريبية وكلمات المرور العشوائية محفوظة في .data المستبعدة من Git. بيانات الاختبار موسومة «بيانات تجريبية». لا تستخدم هذا seed على قاعدة التشغيل. تشمل الاختبارات مسارات المهام والمراجعة والطلبات والاجتماعات والقرارات، إضافة إلى غرفة عمليات الفعالية والجاهزية والاعتماد والحضور على الجوال.

## تنبيهات اقتراب الموعد

`npm run work:due` يرسل تنبيهات داخل التطبيق للمهام والطلبات خلال `WORK_DUE_SOON_HOURS` (الافتراضي 24 ساعة)، مع منع تكرار التنبيه لنفس الشخص والموعد. جَدوله خارجيًا في الإنتاج مع PostgreSQL؛ لم يُنشأ مجدول على جهاز المستخدم. محليًا أوقف Next قبل تشغيل العامل على PGlite. التاريخ محفوظ UTC ويعرض بتوقيت الرياض.

للترقية من المرحلة الأولى: احتفظ بقاعدة البيانات وملف البيئة، أوقف خادم PGlite، ثم شغّل `npm run db:migrate` وأعد التشغيل. الهجرات إضافية ولا تحذف بيانات المرحلة السابقة. تفاصيل المحرك في docs/WORK_ENGINE.md ومحرك الفعاليات في docs/EVENT_ENGINE.md.

## إعداد الإنتاج

- DATABASE_URL لقاعدة PostgreSQL مستقلة مع TLS وفق بيئة الاستضافة، وBETTER_AUTH_URL بعنوان HTTPS، وسر مصادقة مستقل. التطبيق يرفض PGlite في تشغيل الإنتاج.
- npm run db:migrate ثم npm run build ثم npm start. شغّل الهجرات بصلاحية مالك منفصلة عن مستخدم التطبيق؛ لا تمنح مستخدم التطبيق تعديل مخطط قاعدة البيانات أو تعطيل triggers.
- SMTP_URL وMAIL_FROM لاستعادة كلمة المرور. دون SMTP تُعرض رسالة صريحة؛ لا إرسال وهمي ولا حفظ روابط الاستعادة في السجلات.
- احفظ الأسرار في مدير أسرار، واضبط النسخ الاحتياطي والاستعادة وTLS وتدوير السجلات. اختبر استعادة النسخة الاحتياطية واختبارات PostgreSQL الخارجي قبل الإطلاق.
- تسجيل SSO وOAuth يتطلب اعتماد الجهة الجامعية وبيانات موفر الهوية؛ لم يُفعّل في هذه النسخة.
