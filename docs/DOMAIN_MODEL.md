# حدود المجال ودورات الحياة

| المجال | الملكية | الثوابت |
|---|---|---|
| الهوية | حساب، ملف، جلسة، استعادة | بريد فريد، حساب معطل ممنوع |
| التنظيم | لجنة، فصل، عضوية، تعيين دور | الدور ليس حقلًا دائمًا في المستخدم؛ تعيين مؤرخ |
| العمل | مهمة، طلب، اجتماع، قرار | مالك وسياق وفصل؛ انتقالات مصرح بها |
| الفعاليات | مراحل ومتطلبات وحضور | جاهزية = متطلبات مكتملة / إجمالي متطلبات؛ صفر يعني غير محددة |
| الحوكمة | اعتماد، مراجعة، تقرير | خطوات اعتماد محفوظة عند بدء الطلب |
| الأدلة | ملف، مرفق، تصنيف | بيانات وصفية منفصلة عن التخزين؛ تحقق قبل تنزيل |
| الأثر | هدف، مؤشر، إنجاز | قياس له دليل؛ لا منح مكرر |
| التشغيل | نشاط، تدقيق، تنبيه، أتمتة | مفاتيح تكرار، إعادة محاولة آمنة |

## دورات الحياة
الحساب: مُنشأ → تهيئة أولى → نشط ↔ معطل. التعيين: مخطط → نشط → منتهٍ/ملغى، ويحتفظ بالتاريخ. الفصل: مخطط → نشط → مغلق. اللجنة: نشطة → مؤرشفة.

المهمة المنفذة: لم تبدأ → قيد التنفيذ → مراجعة → مكتملة، مع إلغاء وإعادة فتح مصرحين. الطلب: جديد → تم الاستلام → قيد التنفيذ → مراجعة → مكتمل، أو رفض/إلغاء. الاجتماع: مجدول → منعقد/ملغى. القرار: موثق → ملغى. التفاصيل في WORK_ENGINE.md. تقرير الفعالية المنفذ في المرحلة الثالثة: مسودة → مقدم → تعديلات/معتمد؛ وأرشفة الفعالية تتحقق من اعتماد تقريرها إذا كان إلزاميًا. الفعالية فكرة → تخطيط → اعتماد → تسجيل → تجهيز → جاهزية → تنفيذ → تقييم → تقرير → أرشفة.

## الاعتماديات المنفذة والأتمتة اللاحقة
تعتمد المهمة حاليًا على مهمة أخرى عبر FK. تمنع الخدمة الدورات والاعتماد الذاتي والإكمال مع مانع غير مكتمل. التجاوز يتطلب task.override_dependency وسببًا وتدقيقًا. الربط باعتمادات خارج مراجعة المهمة نفسها مؤجل.

الأحداث: id، actorId، action، entityType، entityId، metadata، createdAt، committeeId/ownerId، correlationId. اسم الحدث ثابت مثل task.completed. outbox ينشر بعد commit. قاعدة أتمتة = trigger + condition AST بقائمة معاملات مسموحة + action registry؛ لا eval. فريد (ruleId,eventId)؛ retries محدودة وdead-letter. لا XP قبل دليل حضور معتمد، مع قيد مصدر فريد.

## الفعاليات المنفذة — المرحلة الثالثة

الفعالية نوع event في work_items مع تفاصيل events، وفريق مستقل مؤرخ ومتطلبات جاهزية ومخاطر ومشاركين وحضور وملفات وتقرير. الحالات: فكرة → تخطيط → انتظار اعتماد → معتمدة → فتح التسجيل → تجهيز → جاهزة → تنفيذ → تقييم → تقرير نهائي → أرشفة؛ الإلغاء مسار مستقل. رفض الاعتماد يغلق الفعالية، وطلب التعديل يعيد التخطيط. شروط الدخول والخروج ومتطلبات كل مرحلة والتجاوز موثقة في EVENT_ENGINE.md.

العمل والموافقة والتدقيق يعاد استخدامها؛ القرار يرث فعالية الاجتماع ومهمة القرار ترثها. تقرير الفعالية يجمع النتائج والدروس والأدلة، ويُراجع قبل الأرشفة إذا كان إلزاميًا. القالب ورشة عمل ينشئ المتطلبات والمهام في معاملة واحدة. نسبة الجاهزية من متطلبات فعلية فقط.
