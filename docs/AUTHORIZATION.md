# الصلاحيات والنطاق

Default deny. يحتاج الإذن تعيينًا ساريًا وموسمًا غير مغلق للتعديل، وحسابًا نشطًا. club يمنح النطاق العام لصلاحيات الدور فقط؛ committee يتطلب تطابق اللجنة؛ self يتطلب ملكية المورد. صلاحية المشرف لا تعني تعديل مهام اللجان.

| الدور | النطاق الافتراضي | صلاحيات المرحلة الأولى | امتدادات لاحقة |
|---|---|---|---|
| مدير النظام | النادي | organization.manage, committee.read, committee.update, report.review, audit.read | إدارة السياسات |
| رئيس النادي | النادي | committee.read, committee.update, report.review | event.approve |
| نائب الرئيس | النادي | committee.read, committee.update, report.review | delegated approvals |
| قائد شطر الطلاب | لجان معينة | committee.read, committee.update | عمل الشطر فقط |
| قائدة شطر الطالبات | لجان معينة | committee.read, committee.update | عمل الشطر فقط |
| رئيس اللجنة | لجنة | committee.read, committee.update | task.manage في اللجنة |
| نائب رئيس اللجنة | لجنة | committee.read, committee.update | task.manage في اللجنة |
| عضو اللجنة | لجنة | committee.read | task.update للمالك |
| مشرف النادي | النادي | committee.read, report.review | event.approve؛ لا committee.update |

لا نستنتج نطاقًا من جنس الشخص؛ كل قائد شطر يحصل على تعيينات اللجان المحددة إداريًا. تعيينات startAt/endAt تحفظ تاريخ القيادة. العضوية لا تمنح تعديلًا تلقائيًا؛ الإذن يأتي من الدور. أي تعديل سياسات مستقبلي يحتاج مقارنة قبل/بعد وتدقيقًا.

## التصنيف
عام: محتوى منشور صراحة. داخلي: أعضاء مصرحون. محدود: مالك/لجنة مع صلاحية صريحة. سري: إذن مستقل ومدى حاجة، لا يرث من committee.read. مرحلة التأسيس لا تجمع رقمًا جامعيًا أو هاتفًا لتقليل البيانات. الاستعلامات الحالية تعرض حقولًا محددة ولا تكشف حسابات الآخرين.

## الاختبار
زائر: 401 API وتحويل صفحات للدخول. حساب معطل: 401 حتى مع cookie سليم. عضو أ: لا يصل لجنة ب بتغيير المعرف. مشرف: قراءة فقط دون تعديل لجنة. تعيين منتهٍ: لا صلاحية. جلسة ملغاة: لا وصول. تعديل عبر أصل خارجي: 403. إخفاق المعاملة لا يترك نشاطًا بلا تغيير.

## صلاحيات العمل — المرحلة الثانية

| المجموعة | الصلاحيات |
|---|---|
| المهمة | task.read, task.create, task.update, task.update_own, task.assign, task.review, task.override_dependency |
| الطلب | request.read, request.create, request.accept, request.update, request.complete |
| الاجتماع | meeting.read, meeting.create, meeting.update |
| القرار | decision.read, decision.create |
| الاعتماد | approval.review |

مدير النظام يحصل على المجموعة كاملة. الرئيس ونائبه وقادة الشطر ورؤساء اللجان ونوابهم يحصلون على جميع صلاحيات العمل **عدا التجاوز**، وتظل مقيدة بنطاق تعيينهم. العضو يقرأ عمل لجنته وينشئ مهمة/طلبًا، ويحدث مهمة هو مسؤولها أو مشارك فيها بصلاحية task.update_own؛ لا يعيّن الآخرين أو يراجع تلقائيًا. المشرف يقرأ وله task.review وrequest.complete وapproval.review، دون task.update أو request.update. أي اعتماد يتطلب كذلك تعيين الشخص مراجعًا لتلك العملية، فلا يكفي اسم الدور وحده.

التعليق والمرفق يرثان الوصول للعنصر المفتوح في فصل نشط. الإشارة والمدعو والمسؤول والمراجع يتحقق من أهلية قراءتهم للعنصر قبل إضافتهم. المراجع يحتاج إذن المراجعة النوعي وapproval.review، ولا يعتمد الطلب الذي رفعه للمراجعة بنفسه. task.override_dependency لمدير النظام افتراضيًا فقط، ويحتاج سببًا وتدقيقًا.

في محرك العمل يستبعد التعيين المرتبط بفصل مغلق حتى من القراءة؛ تعيين عام مستقل يتيح قراءة التاريخ إذا كان لديه الإذن. كل تعديل يتحقق أيضًا من حالة فصل العنصر. المحرك يستخدم accessWhere في استعلامات SQL وليس إخفاء أزرار فقط. جدول المرحلة الأولى أعلاه يصف أساس التنظيم؛ هذا القسم يوسع المنح نفسها ولا يستبدلها.

## صلاحيات الفعاليات — المرحلة الثالثة

- event.read/create/update/submit/approve/cancel/archive/override_stage.
- event.manage_team/manage_readiness/manage_attendance/manage_participants/manage_files.
- event.view_budget/manage_budget.

مدير النظام جميعها؛ رؤساء النادي واللجان والنواب وقادة الشطر جميعها عدا override_stage ضمن نطاق تعيينهم. العضو event.read، والمشرف event.read وevent.approve وevent.view_budget ضمن نطاقه. الاعتماد يتطلب أيضًا approval.review وأن يكون الشخص هو المعتمد المحدد ومختلفًا عن مقدم الطلب والقائد.

فريق الفعالية يمنح وصولًا مؤرخًا للغرفة وصلاحيات تشغيلية وفق event_roles؛ لا يمنح تلقائيًا صلاحيات حساسة أو نطاق عمل لجنة أخرى. event.manage_participants مستقل عن قراءة الفعالية؛ صاحب الحضور فقط يرى الاسم والحالة دون بيانات الاتصال أو الرقم الجامعي. الميزانية منفصلة. ملفات participants وbudget تتحقق من الإذن الإضافي عند القائمة والتنزيل. قواعد تعيين الفريق والتجاوز في EVENT_ENGINE.md. صلاحيات محرك العمل السابقة لا تتغير بمجرد event_id.
